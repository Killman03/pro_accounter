Руководство с инструкциями
Интеграция "Конвертированные лиды" использует Conversions API компании Meta для подключения данных о лидах к нашей системе. Загруженные события CRM связываются с идентификатором набора данных и появляются в Events Manager. Подробнее об API Conversions.
1. Проверка необходимых параметров
Вам нужно будет передать эти параметры в API Conversions.
Убедитесь, что вы можете получить эти поля из CRM. Подробнее
События сервера
event_name
Название критического этапа в CRM, на который переходит лид.
event_time
Метка времени UNIX для времени перехода лида на новый этап.
action_source
Поле "action_source" всегда должно быть "system_generated".
Специально настроенное событие
lead_event_source
"Lead_event_source" — это название CRM (HubSpot, Salesforce, SAP, Oracle и т. д.).
event_source
Поле "event_source" всегда должно быть "crm".
Параметры информации о клиенте
Информация о клиенте помогает Meta сопоставлять события, данные о которых поступают с вашего сервера, с аккаунтами Meta. Отправка как можно большего числа указанных ниже параметров может улучшить точность информации о событиях и результативность рекламы

4. Отправка события в Meta
Теперь вы готовы начать загрузку событий в набор данных.
Вы можете отправить тестовое событие или сразу начать отправку рабочих данных.
Отправка рабочих данных
Получение данных из CRM
Проверьте API CRM и убедитесь, что данные из CRM соответствуют требуемым параметрам. И убедитесь, что lead_id совпадает с генерируемым Meta и находится в полезных данных.
Срабатывающие события для изменения статуса лида
Каждая смена статуса лида должна запускать вызов кода. Это должно происходить на каждом этапе воронки, включая начальный этап исходного лида. Эта логика может быть интегрирована в шаг 1 отправки рабочих данных.
Отправка событий в Meta
Напишите функцию с нуля или используйте Meta Business SDK для отправки полезных данных на конечную точку набора данных. Для получения полных инструкций перейдите в раздел "Шаг 4: отправка рабочих данных" в CRM integration guide.
Тестирование события (необязательно)
Отправка тестового события для проверки полезных данных и API-подключения поможет избежать влияния на фактические данные в наборе.
Тестовые события можно отправлять непосредственно с вашего сервера или из GraphAPI Explorer Meta, включив параметр "test_event_code" в полезные данные.
Тестовые события почти сразу же появятся на вкладке тестовых событий в Events Manager.
Обратите внимание, что тестовое событие только подтверждает, что связь была установлена, но не проверяет данные на точность. Для получения полных инструкций перейдите в раздел "Шаг 3: тестирование полезных данных" в CRM integration guide.
Что будет дальше:
Убедитесь, что ваша интеграция загружает данные не реже одного раза в день.
События обычно появляются в Events Manager для вашего пикселя менее чем через час, если интеграция работает.
После того как ваша интеграция заработает, Meta проверит данные. Ошибки будут показаны в разделе "Диагностика".

Параметры
Здесь перечислены все обязательные параметры данных для событий, а также дополнительные параметры, которые Conversions API должен использовать для атрибуции рекламы или оптимизации показов.

Теперь Conversions API поддерживает события на сайте, в приложении и события переписки с компанией.

Для событий с сайта, отправленных через Conversions API, требуются параметры client_user_agent, action_source и event_source_url, а для других — толькоaction_source. Эти параметры способствуют повышению качества событий, используемых для показа рекламы, и могут улучшить результаты кампании.

Используя Conversions API, вы соглашаетесь, что параметр action_source является максимально точным, насколько вам это известно.
